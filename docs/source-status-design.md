# Source-status pilot

## Question

Does elaborating a hypothetical finding increase later reports that it was observed, beyond a similarly sized restatement? Does that difference grow when other case records intervene?

This version removes the numerical fault-ranking task. It measures explicit reports of a finding's status in the original record. It does not measure internal belief, elapsed-time forgetting, or independent recognition of authorship.

## Cases

Each case describes an inspection, a possible cause, and three findings with unique check IDs:

- One finding is reported as an actual completed check result.
- Two findings are conditional predictions from checks that have not been performed.
- A fourth finding is introduced only in the final question, as a foil.

The model classifies all four findings as `observed`, `hypothetical`, or `not_mentioned`. The labels refer to the original case record. A generated note is not allowed to establish a new result. The final question explicitly says its candidate findings are probes, not new observations.

The 32-case pilot contains eight inspection templates and four status rotations per template. Within each template, each finding is observed once, absent once, and hypothetical twice. Case and check IDs are randomized; the foil is absent from note prompts, note schemas, and intervening records. Question order and response-label order are seeded and shared across paired conditions.

The templates share the same formal task. The 32 cases are not 32 unrelated domains, and findings within a case are not independent samples. The four-case configuration is an offline smoke check using a separate seed and one template.

## Four conditions

| Condition | Note | Material before the status question |
|---|---|---|
| `restate_immediate` | Neutral restatement | None |
| `restate_interleaved` | The identical saved restatement | Eight other case records |
| `elaborate_immediate` | Conditional causal explanation | None |
| `elaborate_interleaved` | The identical saved explanation | The same eight other case records |

Both notes are generated by the tested model. Both request approximately 80 words, exactly one mention of each target check ID, conditional wording, and no additional findings. Only the requested writing task differs. The original case and note-writing instructions remain in the decision context, and the saved note is inserted verbatim.

The interleaved condition inserts eight locally generated records in separate user messages after the note. These are supplied records, not additional model-generated conversations or actions. They use different case/check IDs and different inspection templates from the target. The original record and hypothetical labels are never removed or truncated by the runner. The final question and response schema are identical between the immediate and interleaved conditions.

Each case makes two note calls and four classification calls, for a maximum of 192 calls. Call order is seeded and randomized subject to note dependencies. Temperature is zero; the provider may still return variable outputs. There are no automatic retries or note regeneration.

## Outcomes

The primary outcome is the proportion of the two hypothetical findings labelled `observed`, computed within each case. Condition means then average those case-level proportions. A secondary binary outcome records whether either hypothetical finding was labelled observed.

The primary descriptive contrast is:

```
(elaborate_interleaved - restate_interleaved)
  - (elaborate_immediate - restate_immediate)
```

A positive value means the elaboration-associated penalty is greater after intervening cases. It does not establish that elaboration is harmful in either condition by itself; inspect both simple elaboration effects and their directions. The interaction requires all four valid classifications for a case. Simple effects use their own complete pairs, with completeness reported separately.

Control outcomes include:

- All classification errors and the full three-by-three confusion matrix.
- Actual observations labelled otherwise.
- Absent findings labelled observed or hypothetical.
- A recognition diagnostic obtained by collapsing observed and hypothetical into one "mentioned in the record" category.

That recognition diagnostic comes from the same response, not an independent recall test. Correctly labelling a finding as observed or hypothetical distinguishes it from a foil, but does not establish a particular internal memory representation.

Summaries report every planned case, invalidity, complete-pair counts, case contributions, and results by template family. Worst-case bounds assign unknown outcomes their possible minimum and maximum; they are missingness bounds, not confidence intervals. No inferential intervals, significance tests, or deployment-prevalence estimates are supplied.

## Note review and matching

Requested length is matched, not enforced by truncating or regenerating text. Summaries report actual word counts, within-pair length gaps, and literal target-ID mention counts. A 70–90 word band and a pair gap of at most 10 words are descriptive checks only. They never determine which valid cases enter the main analysis. Token lengths and semantic repetition may still differ.

Review both styles in `notes.md`, not just notes associated with classification errors. Check that:

1. The explanation stays conditional and does not claim a predicted result already occurred.
2. The restatement does not itself supply a causal explanation, and the elaboration actually adds one.
3. Neither note introduces a new completed result or an extra check.
4. Length and repetition differences are small enough to interpret the intended comparison.

If a note asserts a false completed result, a later wrong label could be a response to asserted misinformation. It does not isolate confusion caused by using a properly conditional explanation. If a note mentions the foil, record that upstream error: the foil remains absent from the original record, but is no longer an unseen-content control. Automatic literal-ID checks do not establish semantic validity. Keep raw notes and all outcomes; record any review separately.

## Decision after this development run

- First inspect missingness, note quality, and actual-observation/foil controls. Failure here can make the intended comparison uninterpretable.
- Elaboration-associated target errors across multiple cases and templates would justify a frozen follow-up on fresh cases and another model. A single unusual output is not sufficient evidence.
- An interleaving penalty shared by both note styles is evidence of general context difficulty, with little support for a special elaboration effect.
- If status reporting stays accurate, shelve this implementation. This is a decision about research effort, not proof that the effect is absent in every setting.
- Do not remove labels, select failing templates after looking at outcomes, or keep increasing context until a desired effect appears.

Longer input, target position, and competing records change together in the interleaved condition. This pilot does not separate those mechanisms. A positive interaction would also need tighter control of wording, repetition, and note length. The source-status task itself explicitly directs attention to provenance; its rates do not estimate unprompted errors in ordinary use.

## Relation to the original experiment

The original implementation in `design.py` and `analysis.py`, its three configurations, and its tests are retained. The runner selects the new task from `design_version: source-status-v1`; output directories must be separate.

The local six-case fault-ranking smoke run showed no target source-citation errors. Some wrong choices involved numerical ranking or inconsistent answer fields. This redesign therefore changes the measurement rather than treating wrong choices as evidence of contamination. The original run is not pooled with the new experiment, and its raw outputs have not been added to this repository.

## Related methods

- [Reality Monitoring in Large Language Models](https://arxiv.org/abs/2607.23927), 2026 preprint: supplied versus generated word pairs, with immediate and interleaved attribution tests. Conversation history is retained. This motivates the context manipulation; it does not establish the effect for our model or task.
- [Counterfactual reasoning: Testing language models' understanding of hypothetical scenarios](https://aclanthology.org/2023.acl-short.70/), ACL 2023: matched hypothetical-world and actual-world continuations, with lexical controls. This motivates separating hypothetical reasoning from reports of what occurred.
- [Blinded by Generated Contexts](https://aclanthology.org/2024.acl-long.337/), ACL 2024: conflicting generated/retrieved passages, answer tracing, and order, length, similarity, and completeness analyses. This motivates treating prose properties as alternative explanations.
- [How Language Model Hallucinations Can Snowball](https://proceedings.mlr.press/v235/zhang24ay.html), ICML 2024: checkable claims after early answer commitments, independently verified in fresh interactions. The current task removes the original choice-before-evidence requirement.

This is an adaptation of related methods, not a direct replication or a claim of established novelty.
